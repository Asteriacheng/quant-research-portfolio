# 回测防自欺清单 / Backtest Integrity Checklist

> **EN abstract** — Eight mechanical checks every performance number must pass before I am allowed
> to quote it, plus the two structural defences that matter more than any single check: an
> executable-price convention, and a split-date constant that no piece of research code is allowed
> to choose for itself. Includes one method correction I had to make in public: date-shuffled
> future tests give **structural false positives** at the factor level, so factor-level leakage is
> judged by truncation invariance instead.

回测里最贵的不是算力,是**你相信了一个假的数字之后做的所有决定**。
所以这份清单的每一条都写成机械检查:能自动跑的绝不靠自觉。

---

## 一、八项校验(任何胜率/期望/年化出炉前)

| # | 检查 | 不过关会发生什么 |
|---|---|---|
| 1 | **T+1 约束** | 当日买入当日卖出 → 凭空多出一半收益 |
| 2 | **前视排查** | 因子用到了未来数据 → 回测无敌、实盘归零 |
| 3 | **量纲核对** | 成交量「手 vs 股」差 100 倍 → 流动性过滤全废 |
| 4 | **日期复核** | 信号日与成交日错位一天 → 结论方向可能整个反过来 |
| 5 | **缓存一致性** | 中间结果缓存过期 → 改了代码但数字没变,你以为改动无效 |
| 6 | **置换检验** | 打乱标签后收益不消失 → 说明赚的是结构性偏差不是信号 |
| 7 | **独立源抽价** | 用第二个数据源抽查若干价格 → 抓数据源本身的错 |
| 8 | **执行现实性** | 停牌弃单、一字板开盘买不进、跌停卖不掉 → 弃单率必须写进报告 |

第 8 条要特别说:**弃单率高本身就是策略缺陷**。
信号总落在买不进的日子上,意味着回测里赚到的那部分收益现实中根本拿不到。
实现见 `factorkit.filter_executable` / `unbuyable_at_open`。

## 二、两条比单项检查更重要的结构性防线

### 1. 可执行口径写死在数据层

标签一律定义为:**T 日收盘出信号 → T+1 开盘买入 → T+1+H 开盘卖出的超额收益**,
且 T+1 一字板/停牌的样本直接剔除。

理由:研究口径和执行口径一旦分家,分家的那部分收益永远是虚的。
把它编码进标签,比在下游写十条提醒有效。实现见 `factorkit.forward_return(mode="open_to_open")`。

### 2. 切分日期是全局常量,不是研究者的自由度

训练段/留出段的分界线必须**先于一切代码定版**,写在一个单独的边界文件里,
研究代码只能读、不能选。

为什么:自选切分日 = 免费的多重检验。你试三个切分日再选一个「结果好」的,
本质上已经把留出段消费掉了,而且没人看得出来。

配套的三件事:

- **评估计次**:每次留出段评估自动记账,不可关闭;超预算程序拒绝执行;
- **结果粗化**:留出段只回「过/不过 + 粗桶」,精确数字封存——回流的比特越少,
  下一轮设计被污染得越少;
- **诚实声明**:已经被反复看过的时间段,对老策略**没有证据力**,必须明写。
  这条最不舒服,但不写就是自欺。

背后的方程很简单:

```
污染量 ≈ 每次回流的比特数 × 评估次数 × 下游利用效率
```

三个因子分别对应粗化、限次、隔离。只做其中一层的方案都会失效。

## 三、一次必须公开的方法修正

我一开始用 **shuffled-future 置换检验**(打乱标签日期看信号是否消失)当因子层的泄漏探针。
后来发现它对**反转/持续类因子有结构性假阳性**:

- 打乱后的标签窗口可能落进因子的「过去」,而反转因子与过去收益相关**本身是合法信息**;
- 个股固定效应(例如低波股在某个熊市段整体占优)同样会污染这个探针。

因此因子层的泄漏判分改为**截断不变性测试**:

> 把数据截断到某一天重算因子,它在历史每一格上的取值必须与全量算出来的**完全一致**。
> 只要有一格不同(含「一边有值一边是 NaN」),就说明它用到了未来信息。

这是**结构性证明**而不是统计检验:不受因子类型影响,不会被样本噪声糊弄,
而且能精确指出是哪一天哪一只股票出的问题。实现见 `factorkit.truncation_invariance`,
配套的反例(故意偷看未来一天的因子)在 `tests/test_integrity.py` 里——
**一个从来没报过警的检查等于没有检查**,所以我给它准备了必须抓到的对象。

组合级的 shuffled-future 不受这个问题影响,照用。

## 四、多重检验:你试过多少次,决定了门槛有多高

同一段数据上试 1 个因子和试 3000 个因子,需要的显著性完全不同。所以:

- **试验次数由引擎自动计数**,不许研究者自报(自报一定偏低);
- 用 Deflated Sharpe Ratio / PBO 这类**对抗试验次数**的统计量,而不是裸 Sharpe;
- 组内多重检验用 BH-FDR 控制,不是逐个看 p < 0.05。

一个我自己踩过的例子:某策略的边缘效应是真的(效应量稳、方向六年一致、DSR 也过),
但 PBO 高达 75%——因为**配置级精调本身就是对同一段留出数据反复做选择**。
效应真 ≠ 配置可信。这两件事必须分开报。

## 五、最后一条:纪律条款只能当最后一层

```
物理不可能(数据加密、读不到) > 机械拦截(硬编码 raise / 权限 deny / hook)
> 留痕审计(哈希链 + 外部锚 + 周报) > 纪律条款(写在文档里的规矩)
```

每条高危通道至少要有一层机械防线;写在文档里的规矩只作最后一层,
而且必须做到「违反即留痕」。

单机环境挡不住蓄意自欺——这一点要诚实承认。
这套体系防的是**无意泄漏和惯性泄漏**:把违规从「一行代码顺手为之」
变成「必须刻意、必须留痕」的高摩擦动作。
