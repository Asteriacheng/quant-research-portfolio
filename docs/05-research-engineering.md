# 研究工程纪律 / How I Keep a Research Codebase Honest

> **EN abstract** — The operating rules I run my own research under: an append-only issue ledger
> with severity levels, a freeze-fingerprint on config + code so a run cannot silently change its
> own parameters, and post-mortems for infrastructure failures. The working definition of a
> healthy system is not "zero defects" but **"no known defect survives two freeze cycles
> without being fixed, mitigated, or explicitly accepted — and every fix ships with a
> before/after comparison."**

单人做研究最大的风险不是写错代码,是**忘记自己已经知道的问题**。
下面四条是我给自己定的工程纪律,成本很低,救过我很多次。

---

## 一、问题台账:只许追加,不许删行

一张固定格式的表,规则四条:

1. 过程中发现的任何问题,**当天记入**,带编号、严重度、来源;
2. 每个开发周期从台账取修复队列,修完回写状态与验证方式;
3. 每份运行报告末尾必须有「本轮新增问题」一节;
4. **只许追加与更新状态,不许删行**——被证伪的问题标 invalid 留痕。

严重度分四级,决定处理优先级:

| 级别 | 含义 |
|---|---|
| S1 | 影响结论正确性 |
| S2 | 浪费样本或算力 |
| S3 | 与设计稿偏离 |
| S4 | 工程健壮性 |

第 4 条(不许删行)是关键。删掉一条「后来发现不是问题」的记录,
下次遇到同样现象你会再排查一遍。台账的价值在于**它记得比你久**。

---

## 二、冻结指纹:参数和代码不能在跑的过程中偷偷变

一次长时间实验开始前,把 config + 相关代码算一个哈希写进台账;
启动时校验,不符**拒跑**。

它拦住的是这种事:实验跑到一半你改了一个阈值,回来看到好结果,
却已经说不清这个结果对应的是哪套参数。这个机制在我这里真实拦截过一次违规启动。

修复流程固定成一个环:

```
发现问题 → 台账记账 → 周期末汇入修复清单 → 批量修复
→ 重新冻结(参数 + 代码指纹) → 前后对照验证(关键指标 diff)
→ 台账回写状态 → 下一轮
```

**每个修复都必须有前后对照的数字**,否则「修好了」只是一种感觉。

## 三、事故复盘:写清楚根因定没定,别硬编故事

几个真实例子(都记在台账里):

| 事故 | 复盘结论 |
|---|---|
| 长任务两次被外部强杀 | 无 traceback、事件日志无崩溃记录、内存充足排除 OOM;两次时间与某后台维护任务吻合,但**根因未定罪**。缓解措施(每代 checkpoint 原子落盘 + 看门狗自动续跑)先落地,不等定罪 |
| 监控哨兵误报「进程双亡」 | 跨 shell 的引号转义被打碎 → 计数恒空 → 每 2 分钟复活一个看门狗,产生并发写同一个库的风险。**教训:复活型自动化必须故障安全,探针查询失败时宁可静默也不动作** |
| 批处理脚本随机崩坏 | 脚本按 UTF-8 写入但被按 GBK 解析,中文注释的首字节吞掉了后面的 ASCII 字符。**教训:跨 shell / 跨编码边界零内联** |
| 断点续跑与热启动语义冲突 | 恢复时的严格断言基于一个已经不再成立的不变量,导致连续崩溃。修法是放宽断言并**如实记录代价**(续跑轨迹的严格一致性不再保证) |

复盘里最重要的一句话往往是「根因未定罪」。
把没查清的事写成查清了,下次同样的事故会以更贵的形式回来。

## 四、自评要给自己打不及格的分

我给自己那套研究系统逐层打过分,包括:进化闭环 C+、自动化运维 D、模型层「未建」。
结论写的是:「它配得上『严』字,但『自动进化』七个字里,『自动』和『进化』
都只完成了一小半。」

这么写有两个用处:

1. **对外**:一份所有模块都写得同样自信的文档,读者无法判断哪里能信;
   标注了「已验证 / 待验证 / 已证伪」的文档才有信息量。
2. **对内**:排下一步优先级时,不及格的那几项自己会跳出来。

---

## 五、一条操作性定义

「完美的自进化系统」听起来不可达,但可以定义成一个能检查的状态:

> **不是零缺陷,而是没有一个已知缺陷能活过两个冻结周期而不被处理**
> (修复 / 缓解 / 明示接受),**且每个修复都有前后对照验证。**

这条定义的好处是:它可以被检查,也可以被证伪。
